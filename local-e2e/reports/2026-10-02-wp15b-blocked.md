## Reproduction and root cause

Source the handoff `tools/rpc-env.sh` in the same shell, export private ports
48645/48646/48787, and run `pnpm run up --warm-up none`.
Both forks start at the helper's fixed archive pins. The first factory deployment on
Robinhood fails before fund creation:

```text
VM::getCode("SpokeUnwindLib.sol:SpokeUnwindLib")
Revert: vm.getCode: no bytecode for contract; is it abstract or unlinked?
Error: script failed
```

`script/FactoryDeployment.sol:240` passes the unresolved artifact to `vm.getCode`.
`out/SpokeUnwindLib.sol/SpokeUnwindLib.json` has two creation-bytecode link references
to `src/spoke/SpokeCrossChainLib.sol:SpokeCrossChainLib`; the new order executor uses
that linked library. Deployment must link it first, as it already does for SpokeIncomeLib.
This belongs to the parent contract/deployment work, not WP-15b's local-e2e-only scope.
The finding was posted on PR #21. No src/ or script/ files were edited.

Two private-port startup attempts reproduced the failure. The final attempt used the
committed harness after fetching and attempting `git merge --no-ff
origin/feat/pp-sc-feat-fund-closure`; Git reported `Already up to date` because #21 had
not advanced. No artificial merge commit was manufactured. CLI startup cleanup stopped
both anvils; no keeper/API was started. Ports 48645/48646/48787 have no listeners.
