# Agent instructions

## Source licensing

- Read [LICENSING.md](LICENSING.md), [LICENSE](LICENSE),
  [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) and
  [CONTRIBUTING.md](CONTRIBUTING.md) before adding or changing license notices.
- All rights-cleared Pool Party-authored current and future V2 material follows
  the root source-available policy, including unfinished contracts, own
  interfaces, factories, adapters, libraries, tests, scripts, harness,
  documentation and original assets.
- New first-party Solidity files must use
  `LicenseRef-PoolParty-Source-Available-1.0`, rather than a default MIT header.
- Preserve all valid prior MIT grants. External/copied interface definitions,
  unresolved provenance exceptions and `lib/**` retain their identified terms.
  Do not change an upstream SPDX declaration or claim ownership from an import.
- Identify copied/adapted material and obtain the contributor permission needed
  for restricted distribution. A Git author name does not establish ownership.
- SPDX/comment changes can alter Solidity metadata and bytecode hashes. Preserve
  deployed release sources and evidence; never assume a licensing-only source
  change matches the existing verified bytecode.
- Do not describe the current restricted policy as OSI-approved open source,
  revoke historical rights, or treat combined GPL/BUSL/upstream artifacts as
  exclusively Pool Party licensed.
